    Known issues

    Problems you may meet while working with the chart, what causes them and how to work around them. They are Unity Editor behaviors, not chart defects, and the package cannot switch them off for you.

    UI Builder lags and logs EndLayoutGroup errors while you edit a chart

    Symptom. Dragging a numeric field of a chart in UI Builder (a thickness, an offset, the grid size) stutters, and the Console fills with EndLayoutGroup: BeginLayoutGroup must be called first — one error per change. The lag grows with the number of Inspector tabs, Game views and charts on screen.

    Cause. UI Toolkit Live Reload. Every UI Builder edit, saved or not, changes the document asset in memory, and every window with Live Reload on reacts to it:

    • An Inspector tab (Live Reload is off by default for editor windows, but the switch is easy to leave on) recreates its whole window on each change. The error is that recreation happening in the middle of a layout pass; a stock inspector such as a Transform or a Camera produces it just the same.
    • A Game view (Live Reload is on by default for the runtime) re-clones the document's UI on each change, so every chart in it is created and initialized again.

    Live Reload works at the window level; the chart cannot opt out of it.

    Workaround. While you edit in UI Builder, turn UI Toolkit Live Reload off in the ⋮ menu of the Inspector tab and of the Game tab. The switch applies to all windows of the same type. The UI Builder canvas keeps showing the chart live; the other windows stop mirroring every change. Alternatively keep the Inspector and Game tabs hidden behind other tabs while you scrub. See UI Toolkit live reload in the Unity Manual for the details of the feature.
