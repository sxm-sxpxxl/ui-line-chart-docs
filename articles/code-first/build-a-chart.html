Build a chart from code

Goal: a LineChart created in C#, configured through its settings groups, initialized and added to a visual tree — showing the default graph.

Prerequisites: the package is installed (Getting started) and you have a VisualElement to add the chart to (a UIDocument's rootVisualElement, or any container).

Steps

  1. Create the control: new LineChart(). Nothing is drawn yet — the constructor only builds the element tree.
  2. Configure the groups you care about through the properties on the control. Each group is a plain object with documented properties; setting one applies it immediately: Grid, Axis, Legend, and so on.
  3. Call Init(). It builds the chart's model from what you configured and makes the control live. The explicit call matters because you are about to drive the chart from code: the playback methods (Play, Stop, Restart) throw on a chart that is not initialized, and a chart left to initialize itself does so only on the tick after it attaches to a panel — too late for the line that follows. The dataset methods (AddGraph and its siblings) are the exception: they record the change and take effect at Init().
  4. Add the control to your tree. An initialized chart attaches without initializing again. If the control has to be in the tree before you are ready to call Init(), turn Advanced.AutoInitialize off so the tree does not initialize it for you.
public static LineChart BuildAChart(VisualElement parent)
{
    var chart = new LineChart();
    chart.Grid.ColumnsRows = new Vector2Int(6, 4);
    chart.Legend.Side = LegendSide.Right;
    chart.Axis.XAxisCaption = "Time";
    chart.Axis.YAxisCaption = "Value";
    chart.Init();
    parent.Add(chart);
    return chart;
}

Result

A chart with a 6×4 grid, the legend to the right of the plot, "Time" and "Value" as axis captions, and the built-in default graph drawn across it — the placeholder every chart shows until it gets datasets of its own, the same one a LineChart dropped into UI Builder shows.

A chart you only display does not need you to call Init() at all: with Advanced.AutoInitialize on (the default) it initializes itself when it attaches to a runtime panel, which is how the UXML-first track works.
